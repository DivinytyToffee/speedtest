# Замер скорости скачивания

Консольный скрипт на Python 3.9+. Внешние зависимости не нужны.

## Запуск

```bash
python speedtest.py "https://example.com/large-image.jpg"
```

Замените пример на прямую ссылку на существующий файл. URL с параметрами
также передавайте в кавычках. Справка: `python speedtest.py --help`.

## Как работает

Скрипт делает 10 последовательных GET-запросов к одному URL. Каждый ответ
полностью читается блоками по 64 КиБ до начала следующего запроса.
Файл не сохраняется на диск и не загружается целиком в память.
HTTP-перенаправления обрабатываются стандартной библиотекой автоматически.

Время измеряется через `time.perf_counter()`: от начала открытия URL
до полного чтения ответа и закрытия соединения. Оно включает установку
соединения и ожидание ответа. Печать результатов в замер не входит.

Скрипт выводит время и объём каждого запроса, затем:

- Среднее время запроса: сумма времени 10 запросов / 10, в секундах.
- Общий объём: сумма фактически прочитанных байтов тела всех ответов.
- Скорость: общий объём в байтах × 8 / общее время в секундах / 1 000 000,
  в Мбит/с (`Mbit/s`). Это отношение сумм, а не среднее отдельных скоростей.

1 MB = 1 000 000 байт; 1 Мбит = 1 000 000 бит. Заголовки HTTP и служебные
данные TCP/TLS в объём не включаются. Запрашивается ответ без сжатия
(`Accept-Encoding: identity`); автоматическая распаковка не выполняется.

При сетевой ошибке, неполном ответе с известной длиной или статусе, отличном
от HTTP 200, скрипт останавливается с кодом 1 и сообщает номер запроса.
Итоговая скорость для неполной серии не выводится. Ошибка аргументов — код 2,
прерывание Ctrl+C — код 130. Автоматических повторов нет.
Тайм-аут блокирующих сетевых операций — 30 секунд; это не ограничение
общей длительности загрузки файла.

Результат показывает скорость скачивания с конкретного сервера, с учётом
задержек соединения и ответа. На него влияют сервер, маршрут, кэширование
и размер файла. Для замера лучше использовать достаточно большой файл:
он будет скачан 10 раз.
